# k8s-platform

Agent-powered workspace for building a multi-cloud Kubernetes platform (AKS / EKS / GKE) — and a working **demo of [APM (Agent Package Manager)](https://microsoft.github.io/apm/) + [OpenCode](https://opencode.ai)**.

This repo intentionally contains **no infrastructure code yet**. It is a fully-outfitted AI coding environment: engineering standards, security rules, Terraform conventions, incident-response playbooks, and 90+ skills — all declared in one `apm.yml` and compiled into agent-native files. Use it two ways:

- **Demo** — a self-contained example of how APM manages AI-agent configuration across Claude Code, GitHub Copilot, and OpenCode from a single manifest
- **Production** — the actual cockpit for building and operating the K8s platform described in the conventions (Terraform + AVM, GitOps, Prometheus/Grafana, incident response)

---

## What is APM?

[APM](https://github.com/microsoft/apm) is a dependency manager for AI coding agents — think `npm` for agent skills, instructions, prompts, and hooks. You declare what your project needs in `apm.yml`, then:

```bash
apm install    # fetch packages into apm_modules/ (like node_modules/)
apm compile    # generate AGENTS.md, CLAUDE.md, .github/, .claude/, .opencode/ wiring
```

The install→compile split is the payoff: **one manifest, every agent runtime**. This repo targets Claude Code, GitHub Copilot, and OpenCode simultaneously.

Skills and bundles come from curated libraries like [awesome-apm-stacks](https://github.com/thinkjones/awesome-apm-stacks), where each package is a small, readable `apm.yml` of battle-tested sources (1K+ star repos), organised by concern.

## Quickstart (this repo)

```bash
git clone https://github.com/dazmc/k8s-platform.git
cd k8s-platform

# Replay the locked dependency graph — exact same versions as the lockfile
apm install --frozen

# Regenerate the compiled agent files
apm compile

# Start working
opencode
```

You now have an OpenCode session loaded with Terraform conventions, Kubernetes/Docker best practices, OWASP security rules, incident-response workflows, and every skill listed in `apm.yml` — no manual setup per machine.

## How this repo uses APM

### The manifest: `apm.yml`

```yaml
name: k8s-platform-opencode
targets:            # which agent runtimes to deploy to
  - claude
  - copilot
  - opencode
dependencies:
  apm:
    - thinkjones/awesome-apm-stacks/user-core
    - thinkjones/awesome-apm-stacks/architect-cloud
    # ... 7 more stacks, see the file
  mcp: []           # no MCP servers declared here — see "MCP support" below
includes: auto
```

### The stacks

| Stack | What it brings |
|---|---|
| `user-core` | Foundation: skill discovery, verification, review loops |
| `architect-cloud` | Cloud architecture patterns, IaC, cost optimization |
| `architect-devops` | Docker, Terraform, K8s deployment, CI/CD, incident triage |
| `code-core` | TDD enforcement, code review, PR workflows |
| `security-core` | OWASP rules, secure coding standards |
| `test-core` | Integration/E2E testing, Playwright |
| `plan-core` | PRDs, requirements, epic breakdown |
| `plan-docs` | docx/pdf/pptx generation, runbooks, incident comms |

### What's committed vs. generated

| Path | In git? | What it is |
|---|---|---|
| `apm.yml` | ✅ | The manifest — single source of truth |
| `apm.lock.yaml` | ✅ | Pinned resolved graph (commit hashes, content hashes) — reproducibility |
| `.opencode/` | ✅ | OpenCode agents, commands, hooks + **hand-written** platform instructions |
| `AGENTS.md`, `CLAUDE.md` | ✅ (generated) | Compiled instruction files for Copilot/VS Code/OpenCode and Claude Code — marked `<!-- Generated by APM CLI -->`; never hand-edit |
| `.agents/`, `.github/`, `.claude/` | ✅ (generated) | Compiled skills + target wiring — committed so a fresh clone works out of the box; safe to regenerate |
| `apm_modules/` | ❌ | Package cache (like `node_modules/`) — gitignored, regenerable via `apm install` |

**Rule of thumb:** edit `apm.yml` or files under `.opencode/instructions/`; never edit compiled outputs like `AGENTS.md` — your changes will be overwritten by the next `apm compile`.

Note the path-scoping magic in the generated `AGENTS.md`: Terraform rules only load for `**/*.tf` files, Docker rules only for `Dockerfile*`, etc. — so agents get dense, relevant context without bloat.

### Hand-written instructions (the repo's own brain)

`opencode.json` wires three hand-written files into OpenCode that APM doesn't own:

- `.opencode/instructions/platform-conventions.md` — multi-cloud layout, Terraform/K8s conventions, GitOps rules
- `.opencode/instructions/incident-response.md` — SEV1–4 workflows
- `.opencode/instructions/terraform-guidelines.md` — validate/fmt/tfsec flow

These are the "production use" layer: project-specific truth on top of APM's generic stacks. Keep new platform knowledge here, not in the compiled files.

## MCP support

APM can also manage **MCP servers** declaratively — wiring them into whatever runtime you use:

```bash
# Add an MCP server (transport: http, stdio, sse)
apm install --mcp io.github.github/github-mcp-server --transport http
```

The server lands in `apm.yml` under `dependencies.mcp`, gets resolved into the lockfile, and APM writes the correct config shape for each target (OpenCode's `opencode.json`, Claude's `.mcp.json`, Copilot, Cursor, …). Same version-pinning and reproducibility guarantees as skill packages.

This repo currently declares `mcp: []` (skills-only) to stay lean. To demo MCP: install a server, recompile, and inspect the generated configs — the plumbing is the point. Candidates for the production K8s platform later: `azure-mcp` (AKS ops), `kubernetes-mcp-server`, or cloud-provider MCPs for EKS/GKE.

## Day-to-day OpenCode usage

Just run `opencode` at the repo root. You get:

- **Commands** (`.opencode/commands/`): `/code-review`, `/commit`, `/commit-push-pr`, `/review-pr`, `/feature-dev`, `/ralph-loop`, `/help`
- **Platform commands**: `/design-cluster`, `/incident-generator`, `/runbook-writer`, `/devops-oncall`, `/security-auditor`, `/terraform-validator`, `/helm-chart-reviewer`, `/analyze-incident` (K8s-platform workflows — see `.opencode/commands/`)
- **Skills** (~90, in `.agents/skills/`): `azure-kubernetes`, `gke-basics`, `azure-cost`, `tdd`, `diagnosing-bugs`, `brainstorming`, `code-review`, …
- **Agents** (`.opencode/agents/`): code-reviewer, devils-advocate, qa-subagent, prd, and more
- **Loaded conventions**: K8s/Docker/Terraform/security rules are active automatically, scoped to the files being edited

Typical sessions:

```
/design-cluster prod aks        # AKS prod design + Terraform scaffold
/incident-generator SEV2 "API pods CrashLoopBackOff"
/devops-oncall                   # triage the current cluster issue
/security-auditor                # audit manifests, RBAC, network policies
/terraform-validator             # fmt + validate + tflint + tfsec
/code-review                     # review unstaged changes against project standards
> Review this Terraform PR for security issues
> Why did we hit OOMKilled? Draft a runbook.
```

## Known gotcha: fixing APM-deployed files (worked example)

APM packages are written for multiple agents, and sometimes deploy primitives OpenCode rejects — this repo hit exactly that and is a useful troubleshooting example:

**Symptoms after `apm install`:** OpenCode errors or silently ignores `.opencode/agents/*.md`.

**Causes seen here (fixed in commit `f13cc72`):**

1. **Invalid `tools:` frontmatter** — packages listed tool names from other runtimes (`Glob`, `Grep`, `TodoWrite`, `KillShell`, `edit/editFiles`, …) that OpenCode doesn't recognize. Fix: remove the `tools:` list (OpenCode infers tools from context).
2. **Invalid `color:` values** — bare names like `color: green`; OpenCode expects hex or semantic tokens. Fix: `color: "#2ecc71"` (or the newer `success`/`error` tokens).

**Newer APM versions (≥ 0.35.0) regenerate compatible frontmatter** — e.g. replacing `tools:`/`model:` with OpenCode-native `permission:` blocks. If you re-run `apm install` and see agent files change format, that's upstream fixing itself — review the diff, commit it, done.

**General debugging flow:**

```bash
apm install --verbose          # see every file deployed + warnings/collisions
apm audit                      # verify deployed files against lockfile hashes
git diff .opencode/            # inspect what a reinstall changed
```

If an update clobbers a hand-edit, restore from git — APM tracks hashes and warns on collisions, but git is your safety net.

## Maintaining & updating

```bash
# Add a new stack
apm install thinkjones/awesome-apm-stacks/code-python
apm compile

# Pin a version (good hygiene for production)
apm install thinkjones/awesome-apm-stacks/code-core#v1.0.0

# CI: fail if lockfile drifts from apm.yml
apm install --frozen           # exits non-zero on mismatch
apm audit --ci                 # verify on-disk content integrity
```

Commit `apm.yml` + `apm.lock.yaml` together — the lockfile is what makes teammates (and CI) get byte-identical setups.

**Organizational pattern:** wrap your team's choices in an internal package (e.g. `acme/standards`) that depends on awesome-apm-stacks plus private skills; each repo's `apm.yml` then lists one line.

## Switching agents

Proof of the portability claim: change `targets` in `apm.yml` and recompile.

```yaml
targets: [opencode]          # → opencode only
targets: [claude, copilot]   # → Claude Code + Copilot wiring
```

```bash
apm install && apm compile
```

No skill is ever rewritten for a new tool — the compile step emits the right format per runtime.
